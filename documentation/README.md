# documentation/

Stores the durable explanatory material for this project.

## What belongs here

- Project documentation and written specifications
- Design notes and the reasoning behind design choices
- Operating guidance — how things are meant to be run and used
- Reference material intended to remain useful over time

Documentation here should stay accurate as the project changes; update it rather
than letting it drift.

## What does not belong here

- Point-in-time proof and captured output — that belongs in `evidence/`
- Repeatable operating procedures and workflow definitions — those belong in
  `workflows/`
- Handover-specific notes for a transfer — those belong in `handover/`

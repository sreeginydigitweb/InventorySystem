# validation/

Stores the material used to confirm that work is correct before it is handed
over or closed.

## What belongs here

- Validation plans describing what will be checked and how
- Check results recording what was actually found
- Test evidence supporting those results
- Verification records confirming requirements were met
- Quality checks applied to the work

Changes should be validated here before anything moves to `handover/` or
`closure/`.

## What does not belong here

- General project documentation — that belongs in `documentation/`
- Unrelated captured proof — that belongs in `evidence/`
- Throwaway test artifacts created only to make a check pass
